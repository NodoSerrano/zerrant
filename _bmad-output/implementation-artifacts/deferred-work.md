## Deferred from: code review of 4-5-create-task-4-2 (2026-07-27)

- `createTask` no valida nada en runtime: `formData.get("titulo") as string` es un cast de TypeScript, no un chequeo. `titulo text not null` acepta `""`, así que el único guard contra una tarea sin título es el `required` del HTML. Además devuelve `error.message` crudo de Postgres al banner del form. Es el outlier del proyecto: `src/features/profile/actions.ts` sí valida, hace `trim()` y usa una constante `DB_ERROR` para no filtrar mensajes internos. [`src/features/tasks/actions.ts:29`]
- El `textarea` siempre manda `descripcion` en el FormData, así que una descripción vacía se persiste como `""` y nunca como `null`. La columna es nullable. Las pantallas que quieran distinguir "sin descripción" de "descripción vacía" (detalle de tarea, 4.4) van a ver los dos casos iguales. [`src/features/tasks/actions.ts:31`]
- Un doble click muy rápido puede encolar dos invocaciones del server action antes de que `pending` deshabilite el botón, y no hay idempotencia en el insert. Es el patrón `useActionState` + `disabled={pending}` de toda la app (login, onboarding), no algo de esta pantalla. Se arregla de una sola vez o no se arregla. [`src/app/(app)/nodo/tasks/new/NewTaskForm.tsx:129`]
- Sin JavaScript no se puede navegar en ninguna parte de la app: la `TabBar` usa `<button onClick>` en vez de links. El submit del form sí funciona sin JS (progressive enhancement de los server actions), pero el usuario no puede salir de la pantalla. Condición del shell, no de una pantalla. [`src/components/TabBar.tsx:47`]
- El literal `"tourist"` está hardcodeado por separado en la guarda del server component y en la de `createTask`. Si se agrega un tercer tier que no publica, o se renombra el actual, es fácil actualizar una y olvidar la otra — justo el bypass que la doble guarda existe para evitar. Falta una constante o helper compartido. [`src/app/(app)/nodo/tasks/new/page.tsx:27`]
